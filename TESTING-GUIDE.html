How to test a solver that brings receipts

A practical, independent-minded test plan for unsat-with-receipts, the dependency-free Rust CDCL SAT solver.

This is a beginner-friendly test plan. The project has two different kinds of answers: SAT includes a candidate assignment, which you check against every input clause; UNSAT can include a DRAT proof, which a separate checker validates. The point is to verify both without merely taking the solver’s word for it.

Start here. Run commands from the repository root. The solver follows Minisat conventions: exit code 10 for SAT, 20 for UNSAT, and 0 for UNKNOWN. In PowerShell, an UNSAT result is expected—not a failed experiment.

Before you start

  1. Install the Rust toolchain, including cargo. The repository itself has zero Rust dependencies, but Cargo is required to build and run it.
  2. For the comparison stage, install minisat in WSL or another Linux environment. The repository’s comparison script is Bash and is explicitly documented for WSL/Linux.
  3. For proof validation, install drat-trim separately. It is an independent external checker, not part of this repository. The bulk script assumes /root/drat-trim/drat-trim unless you set DRAT yourself.
  4. Optional but useful: have Python available for the independent SAT-model checker shown below. That checker uses only the Python standard library.

Open a terminal in the codebase

In File Explorer, open the unsat-with-receipts folder, click its address bar, type powershell, and press Enter. Or open PowerShell first and change to the repository directory:

cd path\to\unsat-with-receipts

For bash scripts/... commands, open a WSL terminal and change to the same repository through its mounted Windows path. Do not run the Bash scripts in plain PowerShell.

What each stage establishes

1. Rust testsCore parser, DPLL, CDCL, model checks, and heuristic agreement behave as expected on built-in cases.
2. SAT validationA proposed model really satisfies every clause in the original CNF.
3. UNSAT validationAn independent DRAT checker accepts the proof against the exact CNF.
4. Differential fuzzingMany generated instances agree with an independent SAT solver, Minisat.

1. Run the built-in Rust tests

Purpose: this fast local smoke test exercises DIMACS parsing, the older DPLL reference solver, the CDCL engine, the Luby restart sequence, and randomized CDCL-versus-DPLL agreement.

cargo test

Success: Cargo ends with a test summary that reports zero failures. Failure: any test named FAILED, a compile error, or a nonzero error summary. Fix or understand this before moving on. Passing this stage is necessary, but it does not independently establish that large UNSAT claims are correct.

2. Make documented DIMACS test cases

Availability check: this checkout has no checked-in .cnf fixtures. If a colleague gives you a DIMACS file, you may run the main solver on it using cargo run -- path/to/input.cnf. Otherwise, use the two documented demo generators below. They create the exact CNF/proof pairs you need and are the repository’s supplied reproducible samples.

Circuit-equivalence miter

Two independently encoded adders share inputs. The miter is UNSAT exactly when their outputs never differ.

cargo run --release --bin miter -- --bits 16 --proof m.drat --dimacs m.cnf

Success: s UNSATISFIABLE, plus m.cnf and m.drat. That UNSAT result means no input makes the two correct circuit encodings disagree. Failure signal: a missing output file, build error, or a result other than the expected UNSAT. For a negative control, run the intentional bug:

cargo run --release --bin miter -- --buggy

Success: SAT and a decoded counterexample. That matters: it demonstrates that the miter can distinguish non-equivalent circuits.

Sudoku uniqueness

The program solves its built-in puzzle, forbids that exact solution, then proves the second solve UNSAT. That is a uniqueness claim, not merely a successful solve.

cargo run --release --bin sudoku -- --proof s.drat --dimacs s.cnf

Success: a solved grid, then s UNSATISFIABLE, plus s.cnf and s.drat. The final UNSAT statement means the blocking clause made every alternative solution impossible.

3. Independently validate a SAT assignment

This validates an existential claim. For a general DIMACS input, invoke the main solver with no --proof option and save its output. A SAT answer has a v line whose signed integers encode variable values.

cargo run -- path/to/input.cnf > solver-output.txt

Then use an independent clause checker. The following standard-library Python script is intentionally outside the Rust solver; save it as verify_model.py beside your test files, then run it with the CNF and captured output.

import sys

def cnf(path):
    clauses, current = [], []
    for raw in open(path, encoding="utf-8"):
        line = raw.strip()
        if not line or line[0] in "cp%":
            continue
        for token in line.split():
            lit = int(token)
            if lit == 0:
                clauses.append(current); current = []
            else:
                current.append(lit)
    if current:
        clauses.append(current)
    return clauses

def model(path):
    values = {}
    for line in open(path, encoding="utf-8"):
        if line.startswith("v "):
            for token in line.split()[1:]:
                lit = int(token)
                if lit:
                    values[abs(lit)] = lit > 0
    return values

clauses, values = cnf(sys.argv[1]), model(sys.argv[2])
bad = [c for c in clauses if not any(values.get(abs(x), False) == (x > 0) for x in c)]
if bad:
    print("INVALID MODEL; first unsatisfied clause:", bad[0]); raise SystemExit(1)
print("VALID MODEL; all", len(clauses), "clauses are satisfied")
python verify_model.py path/to/input.cnf solver-output.txt

Success: the checker prints VALID MODEL. Failure: it prints INVALID MODEL and identifies an unsatisfied clause. That is a serious discrepancy: preserve the CNF and output before doing anything else.

Why SAT and UNSAT differ: a SAT result says “here is one satisfying assignment,” so direct clause evaluation is enough. An UNSAT result says “no satisfying assignment exists,” which cannot be established by checking a single candidate. That is why the UNSAT path needs a proof and an independent proof checker.

4. Independently validate an UNSAT proof

This validates a universal claim. DRAT is a proof format. The only meaningful check is to give an independent checker both the exact CNF and the proof produced for it. The repository documents drat-trim for this job; install it before attempting these commands.

drat-trim m.cnf m.drat
# expected: s VERIFIED

drat-trim s.cnf s.drat
# expected: s VERIFIED

Success: drat-trim prints s VERIFIED. Failure: any other result, a missing executable, or a missing proof/CNF file. Do not mix files from different runs: a proof is a receipt for one specific formula. The project’s own bulk script defaults to /root/drat-trim/drat-trim in WSL; if yours is elsewhere, set DRAT before running it.

DRAT=/usr/local/bin/drat-trim bash scripts/check-proofs.sh fuzz-corpus

5. Run the Minisat differential-fuzzing workflow

Purpose: this is the strongest routine regression test in the repository. The fuzzer creates mixed random and structured formulas, writes each CNF, records this solver’s answer in ours.txt, writes DRAT proofs for UNSAT cases, and self-checks SAT models. The comparison script then runs Minisat over the same CNFs.

# Generate a small, quick corpus first.
cargo run --bin fuzz -- 100 fuzz-corpus 42

# In WSL/Linux, with minisat installed:
bash scripts/compare.sh fuzz-corpus

# In WSL/Linux, with drat-trim available:
bash scripts/check-proofs.sh fuzz-corpus

Success: the comparison script reports zero divergence lines and the proof script reports zero failures. Failure: a nonempty divergences.txt, a nonempty proof-failures.txt, an ERR verdict from Minisat, or a missing external tool. Start with the 100-instance smoke corpus; only then run the repository’s published-scale reproduction:

cargo run --bin fuzz -- 10000 fuzz-corpus 42
bash scripts/compare.sh fuzz-corpus
bash scripts/check-proofs.sh fuzz-corpus
ArtifactWhat to inspect
fuzz-corpus/ours.txtThis solver’s verdict for every generated instance.
fuzz-corpus/theirs.txtMinisat’s verdicts, created by compare.sh.
fuzz-corpus/divergences.txtMust be empty for agreement.
fuzz-corpus/proof-failures.txtMust be empty for all UNSAT proofs to verify.

A sensible confidence ladder

  1. □ cargo test passes.
  2. □ Run both generated demos and confirm their expected SAT/UNSAT behavior.
  3. □ Check every SAT model with an external clause checker.
  4. □ Check every UNSAT result using drat-trim.
  5. □ Generate a fresh fuzz corpus, compare every verdict to Minisat, and verify every resulting DRAT proof.

That sequence separates three questions often conflated in solver work: “did it run?”, “is the answer correct?”, and “can a separate tool verify the difficult universal claim?”
